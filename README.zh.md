# codeviz：从代码结构里自己"长出"几何

## 运行

**实时模式（推荐）**：双击 `run_live.bat`，或者在终端里运行：
```
run_live.bat demo.py
```
Blender 打开后：
- 改代码并保存，场景会自动重建。
- **点击任意结构，按 N**：右侧 Item 标签里的 CodeViz 面板会显示它的源码（对应的那一行会高亮）、增长规律、被分成的几块、同形和同律的关系。
- 点 **Focus** 聚焦到这个结构，点 **Show all** 回到全景，点 **Open in editor** 在 VS Code 里跳到对应行。
- 面板底部列出了所有结构，点名字就能直接跳过去。

过大的结构会自动缩小，并标注缩放比例（例如 1:3.9）。

**只出一张图**：
```
"C:\Program Files\Blender Foundation\Blender 5.1\blender.exe" -b --python blender_live.py -- demo.py --render shot.png
```
**不开 Blender，在终端里看分析结果**：
```
python analyzer.py demo.py
```
**无人值守地测试图形界面**：设置环境变量 `CODEVIZ_SELFTEST=out.png`（可选 `CODEVIZ_FOCUS=2` 指定聚焦第几个结构），Blender 会自动聚焦、截图，然后退出。

## 原则：只有规则，没有概念

`analyzer.py` 里只有 8 条组合规则（文件开头列着），没有出现过"正方形""三角形""圆"这类词。

| 规则 | 含义 |
|---|---|
| R1 | 一个非负整数量 = 一段长度 |
| R2 | 乘法 = 张成一个新方向 |
| R3 | 加法 = 首尾拼接 |
| R4 | 循环变量 = 某条轴上的位置 |
| R5 | 累加 = 把每次的贡献放在它发生时的循环位置上 |
| R6 | 集合 = 格子，嵌套一层多一个方向 |
| R7 | 只有真正执行到的代码才算数（条件会"切掉"形状） |
| R8 | 调用 = 在调用者下面深一层；连续的调用首尾相接（同 R3） |

**相似性的判断从不看名字：**
- **同形**：把所有输入都设成 N，在多个 N 下比较格子集合，允许旋转和镜像。
- **同律**：格子数量随 N 变化的多项式相同（只比较二次及以上，线性巧合太多）。
- **非多项式**：如果每一步都乘一个稳定的比例（波动 < 3%），报告这个比例。
- **对数**：如果 N 翻倍时，数量总是增加一个固定值，报告 c·log₂N。这条规则只对还没有规律的函数、在大 N 下检查；一旦发现"N 翻倍、数量也翻倍以上"，就立刻放弃这个候选。
- 只有"入口函数"（没有被别的函数调用的）单独分析，辅助函数出现在调用者的调用结构里。

## demo.py 里"自己长出来"的东西

| 代码 | 出现的形状 | 系统自己发现的关系 |
|---|---|---|
| `x * x` | 正方形 | 和 `[[0]*n for _ in range(n)]` 同形 |
| `a * b * c` | 长方体 | |
| `for i: for j in range(i): count += 1` | 阶梯（三角） | 和 `total += i` 同形；和 `n*(n-1)//2` 同律（高斯求和） |
| 带 `if (x-r)**2+(y-r)**2 <= r*r` 的双层循环 | 圆盘 | 计数不是多项式 |
| 三层 `j < i, k < j` | 四面体 | (N³ − 3N² + 2N)/6 |
| `(x+1)*(x+1)` | 正方形，自动分成 x·x、1·x、1·1 三块 | 配方 x²+2x+1 的几何证明 |

## 已知局限

- 只支持 Python 子集：算术、for/while/if、列表推导、`sum`、函数内联。
- 不支持的运算（`-`、`/`、`%`）只保留数值，画成一条长度条。
- 超过 3 维的结构会把多出来的维度折叠成高度。

## 测试

```
python -m unittest test_analyzer -v
```
`test_analyzer.py` 有 29 个测试，分七组（另外三组是 Mutation、HeldOut、Recursion）：

- **Rules**：每条规则单独产生的格子坐标对不对。
- **Similarity**：同形、同律能不能认出来，不同结构会不会被误合并，镜像算不算同形。
- **NamesDoNotMatter**：故意把函数命名成 `square_area`、变量命名成 `circle`，结果必须和诚实命名时完全一样。
- **Robustness**：语法错误、死循环、不支持的语法、运行时错误都不能让程序崩溃。

`#viz n=5` 只影响显示时的尺寸，不影响同形/同律的判断。

## 盲测（heldout.py）

`heldout.py` 由一个**没看过 analyzer.py 的子 agent** 按教科书写法写成，共 12 个经典算法。系统自己发现的关系：

- 冒泡排序、插入排序、选择排序、数 i<j 的配对：**同一个阶梯形**，计数都是 (N²−N)/2。
- 杨辉三角 ≅ 数子数组：带对角线的阶梯，计数 (N²+N)/2。
- 朴素矩阵乘法：结果是 N² 的平面，但工作量是 **N³ 的立方体**。
- 平方和：四棱锥，计数 (2N³+3N²+N)/6。
- 二分查找、素数筛：正确地判断出计数**不是多项式**。

盲测暴露并修好的 bug：下标赋值（`arr[j] = ...`、交换）原来不会执行；`append` 不支持；`if` 判断不算"访问"。

## 递归盲测（heldout_recursion.py）

同样由没看过代码的子 agent 写成，8 个经典递归算法：

- 阶乘：一条直线（只调自己一次）。
- 斐波那契：左右不对称的结构；返回值的增长比例 **≈ 1.618**，系统自己算出了黄金比例。
- 汉诺塔：完美对半的结构，增长比例 ≈ 2。
- 归并排序：对半切的结构，`merge` 调用用另一种颜色显示在里面。
- 快速排序：结构偏向一边，因为这组数据让主元总是最小值。形状取决于真实数据。
- 子集生成：自相似（分形）的形状。

递归盲测暴露并修好的 bug：切片 `arr[:mid]` 不支持；链式赋值 `i = j = 0` 只赋了第一个；辅助函数被单独拿出来分析，产生无意义结果。

## 让 Claude 命名和解释（explain.py）

**顺序很重要：** 几何先由规则生成，Claude 只在形状已经存在之后才看到它。Claude 改不了任何格子、规律或关系，只能给它们起名字、做解释。如果代码里的命名和几何形状对不上（比如函数叫 `square_area`，实际画出来却是三角形），Claude 会把它标出来（显示为 `(!)`）。

准备（只需要做一次）：
```
pip install -r requirements.txt
ant auth login        (或者设置环境变量 ANTHROPIC_API_KEY)
```

用法：
- **在 Blender 里**：点侧栏的 **Ask Claude to explain**。它在后台运行，Blender 不会卡住；完成后，面板和 3D 标注会自动出现紫色的 "Claude:" 名称和解释。
- **在终端里**：`python explain.py demo.py`。加 `--dry-run` 只打印将要发送的内容，不会真正调用；加 `--lang en` 改为英文。

结果会缓存在 `demo.py.explain.json`。代码没变就不会重复调用，也不会重复收费；代码一改，面板会提示"代码已改，解释过期"。

测试：`python -m unittest test_explain`。这组测试用假客户端，不联网，也不花钱。
